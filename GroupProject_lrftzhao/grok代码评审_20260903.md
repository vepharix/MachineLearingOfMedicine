# 临床 ML 代码评审（T1 + 打法 E，首轮）

结论先说：**主 AUC 没有明显的切分泄漏，0.846 作为「本随机 test 上的排序能力」说得过去；不能上 slide 的是工作点表、SAPS 的 Brier、以及把 0.846 写成可部署的临床数字。** 最大的错是评估口径，不是模型没调好。

## (1) 数据泄漏或评估口径错误

按严重程度。病人内部 48h 聚合本身（first/last/min/max/mean）规范允许，不算跨样本泄漏。真正的问题在「用了 test 的标签/尺度」和「观察窗没锁死」。

### 1. 阈值–告警表在 test 上反推工作点（最重）

`code/stage3_5_t1_baselines_models.py`：

```python
thr = pd.concat({"logreg": threshold_table(y[te], p_lr), "rf": threshold_table(y[te], p_rf)}, ...)
```

`common.threshold_table` 用 `roc_curve(y, p)` 再 `argmax(tpr >= s)`，等于**用 test 标签去找刚好达到 70/80/90/95% 灵敏度的阈值**。于是表里的 sensitivity 是按定义钉死的，PPV、每 100 人告警数、漏诊数都是事后最优，不是锁定工作点后的前瞻表现。

打法 E 同样在 test 上选点：`stage_E_label_sensitivity.py` 里 `threshold_table(y_in[te_ok], p_in, sens_targets=(0.90,))`。

规范写得很清楚：test 锁死；**工作点由警报负担决定**。负担数字若从 test 反推，就是用答案调决策规则。

**修法：** 只在 `val` 上跑 `threshold_table`，把阈值写入例如 `output/t1_operating_points.json` 并冻结；test 上只用该阈值数 TP/FP/FN/alerts/PPV。主表只报 test。E 的 90% 灵敏度点沿用 T1 冻结阈值，不要在 `te_ok` 上重选。现在这张 `t1_threshold_table.csv` 不能进 deck。

### 2. 观察窗没有锁在 48h——时间泄漏面未关闭

`load_long` 算了 `minutes`，`build_features` 从未过滤，也没有 `assert long["minutes"].max() <= 48*60`。`last/min/max/mean/count` 用的是文件里的全部时间戳。

PhysioNet 2012 式 release 通常已截到 48h，**现在的 0.846 可能碰巧没吃到未来**；但代码没有保证。一旦混入 48h 之后的 GCS/乳酸/尿量，`*_last` 就是结局泄漏，AUC 会虚高且无法与 SAPS-I（24h 评分）比。

**修法：** `clean` 之后立刻 `long = long[long["minutes"] <= 48*60]`，并打印/断言最大时间。T3（≤24h）必须走同一过滤器，不能靠「release 应该已经截过了」。

### 3. SAPS-I / SOFA 基线用全数据 `max` 缩放，Brier 与模型不可比

```python
s = lab[score].fillna(lab.loc[tr, score].median())
results[f"baseline_{score}"] = metrics(y[te], s[te] / s.max())
```

- `s.max()` 在 **train+val+test 填补后** 上取，test 里若有更高分，全体「概率」跟着变。这是跨样本尺度泄漏。
- 排序指标（AUC-ROC/PR）对正比例缩放不变，**0.642/0.622 作为排序基线仍可用**。
- `s/s.max()` 不是概率。SAPS Brier 0.186 差过全猜 0（0.142）和猜患病率（≈0.122），不能拿来和 LogReg Brier 0.092 比「校准更好」。

**修法：** 填补中位数只用 train（已做，保留）。AUC 直接用原始分数 `s[te]`。要报 Brier/校准：在 train 上拟合 **单变量 logistic** `P(y|SAPS-I)`，test 上 `predict_proba`。这才是「只用 SAPS-I」的模型基线。

### 4. 多数类基线的 AUC-PR 不是「模型」

`metrics(y[te], np.zeros(len(te)))` → AP=0.142，恰等于患病率。常数预测的 PR 曲线退化，只能当无信息参照，不要写成「基线 PR 0.142」。ROC 0.5 没问题。

### 5. 打法 E 重训了「院内模型」，不是冻结 T1 的敏感性分析

规范：同一特征表、同一切分、**不换主标签**；E 是敏感性分析。代码却 `m_in = make_model(...).fit(X.loc[tr_ok], y_in[tr_ok])`，丢掉 val、丢掉 16 名 `death_30d` 缺失的 train 病人，C 还是按院内标签在 val 上选的。

数字上 0.8463 vs 主结果 0.8462，几乎没差；概念上这已经不是「原模型被平反多少」。

**修法：** `train_inhospital__eval_*` 读 `t1_test_predictions.csv`，在 `te_ok` 上重算指标。只有 `train_30d__*` 才允许重拟合。工作点用第 1 条冻结的阈值。

### 6. `Urine_sum` 把「没测过」写成「尿量 0」

```python
wide["Urine_sum"] = (...).reindex(wide.index).fillna(0)
```

没记尿量的人看起来像无尿，而无尿强烈指向死亡。若 `measured_Urine` / `Urine_count` 在冻结表里，LogReg 还可以拆开；若实际 `features.csv` 只有 first/last（你贴的列名在 `pH_last` 截断，**先数一下是不是 200+ 列、有没有 `measured_*`**），这就是直接的假信号。

**修法：** 无记录保持 NaN，或只在 `Urine_count>0` 时写 sum；缺失交给指示列。禁止 `fillna(0)` 当无尿。

### 7. 随机切分上的总体 AUC，不能当成「未见数据」表现

切分本身：60/20/20、`stratify=In-hospital_death`、`random_state=2026`、Pipeline 只在 train 上 fit 插补/标准化——**这一段是对的**，病人内聚合冻进 `features.csv` 也不算切分泄漏。

错在口径：同一医院系统、同分布随机抽 test，只证明「打乱后还能排」。规范把**打法 C（留出一类 ICU）**定为必做，且点名 CSRU 4.9% vs MICU 19.8% 时校准必崩；Topic 05 要求年龄/性别亚组。这些没做，0.846 不能写成可迁移性能。

**修法：** 主数字仍用这一次冻结切分（不要重切刷分）。另做：去掉 `ICUType` 后 leave-one-ICU-type-out；test 上按 ICUType / 年龄带 / Gender 分层报 AUC、校准、患病率。总体只保留一行。

### 8. 「test 锁死」在脚本结构上不成立

`stage3_5_t1_baselines_models.py` 把选 C、fit、test AUC、阈值、校准、OR、写预测打在一次运行。LogReg 的 C 只看了 val（合格），但 test 指标已经看见。再改特征/网格后重跑，test 就会被迭代污染。

**修法：** 拆 `fit` / `eval`。选超参只读 val；test 评估单独脚本、结果入 `t1_metrics.json` 后不再为提高它改模型。RF 若要调参，只许用 val，现在那种「fit 完立刻看 test」的写法禁止用于调参。

## (2) 代码 bug / 与方案不符

**建模缺口（规范 Stage 4/6）**

- T1 只打了 LogReg 和 RF，缺决策树、缺 XGBoost。规范链是 LogReg → 决策树 → RF/XGBoost，用来讲复杂度/过拟合，不是多刷一个 AUC。
- RF 完全没在 val 上选参（`n_estimators=400, min_samples_leaf=5` 写死），却报了 `val_auc` 0.860。那是事后描述，不是模型选择。
- 树模型没有 permutation importance、没有 PDP；LogReg 的 OR 是 200+ 列、first/last/min/max/mean 高度共线下的逐列 `exp(coef)`，规范写明**成组解读**。现在这张 `t1_logreg_odds_ratios.csv` 不能当「GCS 的效应」。
- `ICUType`、`Gender` 当连续变量进 `StandardScaler` + LogReg。`ICUType` 1–4 无序，CSRU vs MICU 死亡率差 4 倍，ordinal 编码是错的。规范明确 ICUType 入院即知、应进特征，但要 **one-hot**（打法 C 时再拿掉）。分类变量插补用 median 也不对，应用 mode。

**超参落在网格边界**

- LogReg 网格 `{0.01, 0.03, 0.1, 0.3, 1.0}`，选中 **C=0.01（最强正则、左端点）**。没搜到最优，只说明 200+ 共线列需要更强收缩或先把 min/max/mean/last 成组。应向下扩到 `1e-3/3e-3`，或先按变量族降维再搜。
- 选定 C 后只在 train（60%）上重拟合，没用 train+val。这不是泄漏，是浪费样本；锁 C 之后在 train+val 重拟合再测 test 是标准做法。

**清洗**

- `Height==0` 或负值：`<10 且 >0` 才 ×100，`10–100 或 >230` 才置 NaN，**0 会留在表里**。Weight 有 `<=0` 规则，Height 没有。
- 相对「数据集速览 §五」：Temp 只丢 `<25`，无上界；GCS、HR=0、K 过低、pH 纠正后 `>7.8` 等未处理。`replace(-1)` 在聚合前，这条纪律是守住的。
- 硬矛盾 3 例（100348/105677/108861）、死亡者 Survival=1 仍有 85 例、LOS=1 的 5 例：T2 的 `t2_valid` 能剔 LOS=1，T1 没有记录这些数据质量清单。规范要求进 limitations 素材，代码没有产出。

**打法 E 标签**

- 定义与规范一致：院内死亡 **或** `Survival−LOS≤30`；`Survival` 未进 features，assert 也有。合法。
- `d30[surv<=0]=0` 把随访期内未死（含 −23）当成阴性，与规范一致；LOS 缺失且已死亡的才是 NaN，test 7 人、train 16 人，合理。
- 名字 `death_30d` 容易被讲成「入院 30 天死亡」。实际是**院内死亡 ∪ 出院后 30 天死亡**（住院第 60 天院内死亡仍是阳性；出院后第 35 天死亡是阴性）。Deck/JSON 里应改名，例如 `death_inhosp_or_30d_post`。
- 它不是入院 30 日死亡率，也不是「标签错了 28%」的证明。

**其它规范缺口（本包范围内）**

- T2 未跑：中位数基线、log1p/expm1、test 上 Σŷ vs Σy 都不存在。T1 评审不据此扣「T1 做错」，但地基号称两任务共用，T2 有效集必须是本切分的子集，现在没有验收。
- 打法 C 规范为必做，未做。
- `features.csv` 请核对列数。代码会生成 min/max/mean/count 和 `measured_*`；你贴的列名停在 `*_last`。若冻结文件真的只有 first/last，Stage 1 没完成，MNAR 故事没有变量。

## (3) 结果怎么读

### SAPS-I AUC 0.642 是否合理

**方向合理，略偏低，可作排序基线，不可作概率基线。**

- 本队列院内死亡 14.2%、n_test=2400，和 PhysioNet 2012 口径一致。文献里该挑战的 SAPS-I 对院内死亡大约 **0.65–0.70**；SOFA 相近或略弱。你这边 SAPS 0.642、SOFA 0.622，都明显 >0.5、明显 < 48h 汇总特征模型，形态对。
- 偏低的原因要写在脚注，不要假装「SAPS 只有 0.64」：① 518 例 SAPS-I=−1 用 train 中位数填，歧视度被稀释（应另报「完整评分子集」AUC）；② SAPS-I/SOFA 是 **24h** 评分，模型吃 **48h** last/min/max，对比不公平；③ `s/s.max()` 不影响 AUC，但不要连带报 Brier 0.186。
- 多数类 ROC 0.5、AP=患病率：无信息参照成立。入场券是「打败 SAPS/SOFA 的**排序**」，目前 0.846 vs 0.642 这一条过了；入场券不是 Brier、也不是「ML 比临床评分神奇 0.20」。

### 模型 AUC 0.846 是否可信

**作为「本冻结随机切分、48h 汇总特征、排序能力」——大致可信；作为临床性能数字——还不可信。**

支持可信的证据：

- LogReg 0.8462 与 RF 0.8460 几乎相同，AP 0.507 / 0.519，都远高于患病率 0.142。这不像单棵树过拟合或 test 泄漏（泄漏时往往树 ≫ 线性、val≈test≈虚高）。
- LogReg 的 C 只在 val 上选；插补/缩放在 Pipeline 里。val 0.872 → test 0.846（−0.026），RF val 0.860 → test 0.846（−0.014），有落差，不像 train/test 串了。
- PhysioNet 2012 上，48h 统计特征 + 线性/森林，公开复现多在 **0.82–0.88**。0.846 落在区间内，不是 0.95 那种必有泄漏的数。
- test 约 341 例死亡，DeLong 标准误大约 0.01–0.02。报点估计 0.846 而不带区间，精度是假的；但相对 SAPS 的差距（~0.20）足够大，不是抽样噪声。

必须打折扣的：

- 代码没锁 48h，0.846 的前提是「release 真的只有 48h」。这是未验证假设。
- C=0.01 在网格左端，LogReg 还没调完；val 比 test 高 2.6 个点，deck 只许报 test。
- 没有 ICU/年龄/性别分层，没有打法 C。CSRU 基础率 4.9% 时，同一模型的 **AUC 可能还在，校准不会在**。
- 校准：LogReg 分位箱大体贴对角线，高段 0.279 vs 0.329、顶箱 0.573 vs 0.567，**排序可用、概率勉强**；RF 顶箱 **0.442 vs 0.567**，高危段系统性低估，概率压缩。规范口径直接套：只用于排队复核；**RF 不许把「44%」说出口**；LogReg 也未做外部校准，个体风险数字仍不要说。
- 工作点表（sens=0.90 时每 100 人 ~47 次告警、PPV~0.28、漏 33 人、假警报 810）是 test 上拟合出来的，**乐观**。即便数字量级不变：复核 47% 的入院者，是否还叫「廉价第二意见」，要在问题陈述里重答，不能只展示灵敏度 90%。

### 打法 E 的数字说明了什么

先把算术写对（test 可判定 n=2393）：

| 量 | 数 |
|---|---|
| 院内阳性率 | 14.25%（~341 人） |
| 放宽后阳性率 | 17.13%（~410 人） |
| 出院后 30 天内死亡 | **约 69 人**（全队列粗算 300+，不是 2848） |
| 90% 灵敏度点上 FP | 812 |
| FP 中 30 天内死亡 | 56（6.9%） |
| 院内存活者中 30 天死亡基础率 | 69/2052 ≈ **3.4%** |
| 重训 30 天标签后的 30 天 AUC | 0.840，**不超过**「院内模型直接拿去评 30 天」的 0.842 |

说明三件事，且不要多说：

1. **标签偏窄是真的，但窄在「几十到三百人级的早期出院后死亡」，不是「四分之一标签错了」。** 2848 人随访期死亡、中位 328 天，那是 ICU 人群长期死亡；E 的 30 天窗只多抓了约 69/2393。与规范一致。
2. **模型给这批人打偏高分，有弱证据，不是主因。** FP 里 30 天死亡 6.9% vs 存活者基础率 3.4%，大约 2 倍富集；56/69≈81% 的这批人落在 90% 灵敏度的大网里——但这张网罩了近一半队列，高覆盖几乎是设计结果。**756/812（93%）的 FP 在放宽标签后仍是 FP。** 禁止写成「假警报其实是标签错了」。
3. **换标签不值得开新任务。** 院内模型评 30 天：ROC 略降（0.846→0.842），PR 上升（0.509→0.557）主要是患病率从 14.2%→17.1%，不是排得更好；用 30 天标签重训，30 天 AUC 反而不如原模型。Brier 变差是因为原模型仍按 ~14% 出数、真值变成 17%。E 的合格结论是一句：**主标签保持院内死亡；出院后早期死亡是 limitations 里的低估，不是新 endpoint。**

E 里 RF 的交叉格（30 天训、院内评 AUC 0.850）不要解读成「换标签更好」，样本量同一 test、差 0.003，噪声。

### limitations 该怎么写

按规范三条写满，并用本轮数字收口，不要用 E 洗短处。

1. **自我实现 / 干预混淆。** 高危预测若触发复核或加干预，获救者在院内死亡标签下变成「假阳性」。本模型无法从观测数据里拆开。所以只承诺排序复核，不承诺预测「将会死亡」。
2. **confounding by indication。** 前 48h 有创血压、机械通气、频繁化验（`count`/`measured_*`）预测死亡，部分因为病重才被测量/上机。OR/重要性必须成组讲，禁止「上呼吸机导致死亡」。`Urine_sum` 填 0 会把没测写成无尿，属同一类，要先修再解释。
3. **院内死亡低估真实短程风险；但大头不是标签错误。** 随访期有死亡日期的出院者约 28%，中位生存 328 天——那是长期死亡率。真正与复核窗口相关的，是出院后 30 天内约数百人（本 test 69 人）。他们的 SAPS 介于长期存活与院内死亡之间；模型打高分 ≠ 误报。E 显示其中富集很弱、换标签不提升，故**不改主标签**。另：LOS/Survival 错位（死亡者中位差 1 天；403 例差 >2 天；Survival=1 而 LOS=38/52；硬矛盾 3 例；官方不应有的 Survival=1 共 85 例）是抽取质量问题，不是「死后占床」。T1 用院内死亡官方列，不受 Survival 钟影响，但数据质量必须点名。
4. **（本轮应加的第四条）校准与工作点。** 主指标 AUC 只支持排队。LogReg 校准尚可、RF 高危段不可用。工作点必须按警报预算在 val 上锁；当前 90% 灵敏度对应约一半人告警，若复核成本被问住，问题陈述要降灵敏度或缩小行动定义。禁止报未经锁定的 PPV。
5. **（第五条）泛化未测。** 单一随机切分；四类 ICU 基础率差 4 倍；无时间外/病房外验证。0.846 不是外院数字。粒度：LOS 为整数天；T2 若做，个体出院日不准承诺。

不要写的话：「四分之一标签错了」；「误差在队列上相消所以可用」（T2）；「容量/ICU 床位」（LOS 含 ICU 后病房日）；「模型概率 40%」。
