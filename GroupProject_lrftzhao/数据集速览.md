# 小组项目数据集速览

> 对 `release/` 的一次完整体检。**所有数字都是我实际跑出来的**，不是从 README 抄的。
> 生成时间 2026-08-26。

## 一、这是什么

**PhysioNet/CinC Challenge 2012** 的 ICU 数据（Predicting Mortality of ICU Patients）。
12,000 次成人 ICU 入住，涵盖心内科、内科、外科、创伤 ICU；**住院不足 48 小时的已被排除**。每条记录只覆盖**入 ICU 后的前 48 小时**。

| | |
|---|---|
| `icu_records/` | 12,000 个 `<RecordID>.csv`，长表 `Time,Parameter,Value` |
| `outcomes.csv` | 12,000 行 × 6 列 |
| 总观测行数 | **5,285,818** |
| 每份记录行数 | 中位 430，四分位 361–511，最少 6，最多 1502 |
| RecordID | 100001–112000 **连续无缺口，无重复** |

文件名与文件内 `RecordID` **完全一致**，`outcomes.csv` 的 ID 集合与文件集合**完全吻合**——这两项都核对过，不用再验。

## 二、预测什么

`outcomes.csv` 五个候选列里，**只有 `In-hospital_death` 适合当预测目标**：

| 列 | 能不能当 target | 能不能当特征 |
|---|---|---|
| `In-hospital_death` | ✅ **主选**，0/1 | — |
| `Length_of_stay` | 可以（回归），但见下 | ❌ 出院才知道 |
| `Survival` | ❌ | ❌ **严重泄漏，见下** |
| `SAPS-I` / `SOFA` | ❌ | ⚠️ 可以，但要想清楚 |

**类别分布**：死亡 1,707 / 存活 10,293 → **死亡率 14.2%**。
属于中度不平衡（86:14），正好落在 Topic 04 说的「AUC-ROC 适用区间（70-30 到 90-10）」。**accuracy 会骗人**——全猜存活就有 85.8%。

## 三、泄漏：三个必须先处理的

### 1. `Survival` 是完美泄漏源，必须丢掉

| | 有 Survival 值 | Survival = −1 |
|---|---:|---:|
| 院内死亡 | **1,707** | **0** |
| 存活 | 2,883 | 7,410 |

**每一例死亡都有 Survival 值，每一个 −1 都活着。** 而且量级也在泄密：死亡组中位 **7 天**，存活组中位 **337 天**。留着它，模型分数会好看到荒谬，但那是把答案读了回来。

### 2. `Length_of_stay` 是未来信息

在第 48 小时做预测时，住院总天数还不存在。当特征是 temporal leakage；当 target 则要接受它只在出院时可知。另有 **167 行是 −1**。

### 3. `SAPS-I` / `SOFA` 要想清楚

这两个是严重度评分，**基于入 ICU 头 24 小时**计算，所以时间上不算作弊。但它们本身就是「死亡风险」的浓缩，放进模型等于让它抄一个已经很强的临床评分——**基线该打败的正是它们，而不是把它们当特征**。缺失 518 / 403 行（−1）。

## 四、缺失：`−1` 是占位符，`isna()` 一个都看不见

和 Topic 02 的 `"?"`、Practice Quiz 的 `999` 完全同类。**读进来先 `replace(-1, np.nan)`**，否则 −1 会作为真实数值参与均值和回归。

`outcomes.csv` 里的 −1：SAPS-I 518、SOFA 403、Length_of_stay 167、Survival 7,410（这个是设计上的「未死亡」，不是缺失）。

**描述符里的 −1：**

| 变量 | −1 行数 | 占比 |
|---|---:|---:|
| **Height** | **5,726** | **47.7%** |
| Weight | 1,001 | 8.3%（在 386,942 行里）|
| Gender | 12 | 0.1% |

Height 近一半缺失，**BMI 这条路基本走不通**，除非接受一半样本没有。

### 变量覆盖率分三层

| 层 | 覆盖率 | 变量 |
|---|---|---|
| 近乎人人都有 | 97–98.5% | HR、Temp、GCS、Urine、BUN、Creatinine、HCT、Platelets、HCO3、Na、WBC、K、Glucose、Mg |
| 一半到八成 | 42–88% | 无创血压 NI\*（87%）、pH/PaCO2/PaO2（75%）、有创血压（70%）、FiO2（68%）、MechVent（63%）、Lactate（55%）、SaO2（45%）、肝功四项（42–43%）、Albumin（41%）|
| 稀疏 | < 30% | RespRate（27.7%）、TroponinT（22%）、Cholesterol（7.9%）、**TroponinI（4.7%）** |

**采样极不规则**：HR 人均 58 次、MAP 52 次、Urine 35 次，而 Cholesterol 人均 1.0 次。建模前必须把长表**聚合成每人一行**（每个变量取 min/max/mean/first/last/count 之类），这一步就是本项目的主要工程量。

### 「有没有测」本身就是信号

- **有创血压（SysABP/DiasABP/MAP，70%）vs 无创（NI\*，87%）**：上动脉导管的是更重的病人。选哪种测量方式**不是随机的**。
- **RespRate 覆盖率只有 27.7%，但一旦记录就人均 49.7 次** —— 明显的两极分布，多半取决于是否上呼吸机 / ICU 类型。
- 这是典型的 **MNAR**：缺失与病情严重度相关。加一个「是否测过」的二元指示列往往比插补更有信息量。

## 五、不可能值：`−1` 之外还有

| 问题 | 规模 | 说明 |
|---|---:|---|
| **血压 = 0** | SysABP 1,891 · DiasABP 1,882 · NISysABP 552 · MAP 86 | 动脉导管掉线/冲管，不是真值 |
| Weight = 0 | 277 | |
| Temp = 0 | 104 | |
| **Temp < 0 °C** | 59（最低 −17.8） | |
| **Height 单位混乱** | 2 个 < 10（写成米，如 1.8）· 15 个在 10–100（可能是英寸）· 11 个 > 230 | |
| **pH 放大 100 倍** | 3 个在 650–800（如 735 = 7.35） | 另有 4 个 ≈ 0 |
| K = 22.9 mEq/L | 1 | 远超致死浓度 |
| **Survival = −23** | 1（RecordID **100348**） | 死亡在入院前 23 天 |

数量都不大，但**血压的 0 值有近 4,000 行**，直接算均值会把血压系统性拉低。

## 六、README 与实际数据的两处不符

1. README 说 Time 从 `00:00` 到 `47:59`，实际**有 1,412 行时间戳是 `48:00`**，最大值就是 48:00。
2. README 那句 "stop at the 48-hour however long the patient actually stayed" 是**残缺的**，中间掉了词。

不影响使用，但引用 README 描述数据时别照抄。

## 七、切分：这次不需要 GroupShuffleSplit

RecordID **无重复**，一行就是一次 ICU 入住。数据里**没有病人级 ID**，所以：

- 用普通的 `train_test_split(..., stratify=y, random_state=...)` 即可，按 `In-hospital_death` 分层
- 与 Topics 01–03 实操那份糖尿病数据**不同**——那份一人多次就诊，必须按病人切

⚠️ 一个无法验证的假设：README 只说「12,000 次 ICU 入住」，**没说是 12,000 个不同的人**。若同一人有两次入住，我们无从识别。这一点应当在报告的局限性里写明。

## 八、建议的下一步

1. **先做长表 → 宽表的聚合**（每人一行）。这是最大的一块工程，也是最容易出错的地方：`replace(-1, nan)` 要在聚合**之前**做，否则 −1 会混进 min/mean。
2. **基线要打三个**：① 全猜存活（85.8%）② 只用 SAPS-I ③ 只用 SOFA。模型打不过这三个就没有意义。
3. **指标选 AUC-ROC + AUC-PR**，不要用 accuracy。14% 阳性率下，PR 曲线比 ROC 更能反映实用性。
4. **缺失当特征用**：给覆盖率中低的变量加「是否测过」指示列。
5. 报告的 Data Quality 一节可以直接用本文件第四、五节——**那些数字都是核过的**。
