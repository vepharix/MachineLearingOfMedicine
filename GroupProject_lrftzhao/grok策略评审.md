## 一、和评分标准对得上的部分

作业四条硬性要求，现在的设计都能交卷：

| 要求 | 你们的对应 |
|---|---|
| 01 ASK：至少 2 个预测任务 | T1 院内死亡 + T2 住院时长；T3 是低成本的 go beyond |
| 02 BUILD：自己训、不用外部 API | 已写进三条纪律 |
| 03 EVALUATE + EXPLAIN：指标有理由、含未见数据、每个模型可解释 | 评估 harness + 阈值表 + odds ratio / permutation / PDP |
| 04 INTERPRET + DEFEND：每人能辩护全项目 | 六环认领 + 周会当 TA + 第二轮抽签换讲 |

v1 按工序切开（数据组 / T1 组 / T2 组 / 叙事组）有三个问题：与要求 04 正面冲突、故事写在最后、features.csv 冻结前下游空转。v2 改成按评分链条的结论认领，修的就是这三处，应该沿用。

和 Topic 05 的项目方法论几乎是同一套语言：先问题后模型、Level 1 autonomy（一级自主：AI 告知、医生决定）、干预决定指标、缺失当信号、校准、亚组。T1 的「廉价第二意见、宁可多复核」几乎是课件 sepsis 仪表盘例子的换皮——咨询课和 Q&A 都好讲。

数据侧的判断也经得住核对：

- 死亡率 14.2%（1,707 / 12,000），落在 Topic 04 说的 AUC-ROC 适用区间（70:30–90:10）边缘
- `Survival` 是完美泄漏，必须丢掉
- `−1` 是缺失占位符，聚合前先 `replace(-1, np.nan)`
- 血压 0 当掉线 / 冲管，不是真值
- SAPS-I / SOFA 当**基线**不当特征（时间上不作弊，但是已经很强的临床评分浓缩）
- T2 的 naive 基线用中位数而不是均值：全体有效 LOS 上，猜均值 MAE ≈ 8.13 天，猜中位数 ≈ 7.42 天

差异化「四选二三」的原则也对：**任务撞车无害，故事撞车才致命。** 全班都会做死亡 + LOS，拉开差距的是别组 slide 上没有的那句话。

## 二、需要改的三处

### 2.1 T2 的临床故事和主分析互相打架

现在的写法是：把个体 LOS 预测**求和**做病房容量预报；同时主分析只在**幸存者**上做，因为死亡者的 LOS 是「到死亡的时间」。

问题在部署语义：第 48 小时并不知道谁会活下来。床位占用来自所有还在院的人，包括将要死的人。只在幸存者上训练，部署时没法用；求和预报也不完整。

那句口头缝合也不经追问：

> 期望床位占用 = P(死亡)×存活时长 + (1−P)×住院时长

`Survival` 含出院后随访死亡；占用只跟**还在医院的天数**有关。对容量来说，每个人的贡献就是剩余住院日，死活都算。

建议改成：

| | 做什么 | 为什么 |
|---|---|---|
| **主分析** | 全体病人；目标改成 **剩余住院日 = `Length_of_stay − 2`** | 前 48 小时已经住过了，再去预测总 LOS 是在猜已经发生的事 |
| **敏感性分析** | 幸存者子集单独再跑一遍 | 「死亡截断 vs 出院」语义不同——这页仍有价值，但它是局限，不是主模型 |
| **两任务缝合** | 同一时点、两个决定 | 要不要复核；这张床大概还要占多久。不必硬做成一个公式 |

T2 **仍然该做**。一分类一回归，Topic 03 / 04 各用满一次，这是对的。只是别把「个体出院日期」或「精确容量」承诺出去——中位数基线 MAE 已经约 7 天，个体预测的天花板大家一眼能看见。v2 里「不承诺个体出院日期」这句要守住，并让主分析与这句话一致。

### 2.2 切分少了 validation，和课件原文冲突

Topic 05 写得很死：**始终切成 train / validation / test，而且在任何跨样本的预处理之前切。** 课件还点名用 cross-validation，调参绝不看 test。

现在的设计是 `stratify=In-hospital_death` 的一次 train/test，切分文件进仓库——防两套划分打架，这点很好。缺的是：

1. **三路划分，或训练集上 k-fold**，test 锁到最后。
2. 标准化、插补、特征选择**只在 train 上 fit**。`first/last/min/max/mean/count` 是病人内部聚合，冻在 `features.csv` 里再切分**不算泄漏**；Scaler / 插补 / 选特征若在 12,000 人全体上 fit，就是泄漏。

「未见数据」的最低限度是锁死的 test set。打法 C（留一类 ICU 做测试）是加分，**不能代替**主报告里的随机 test。还要注意：若 `ICUType` 已进特征，留一类 ICU 测试时要处理未见类别（那一类的 one-hot 全为 0，或这个实验里先拿掉 `ICUType`）。

四类死亡率（本评审复算）差约四倍，打法 C 的校准故事成立：

| ICUType | n | 院内死亡率 |
|---|---:|---:|
| 1 CCU 冠心病监护 | 1,769 | 12.7% |
| 2 CSRU 心外恢复 | 2,530 | **4.9%** |
| 3 MICU 内科 | 4,293 | **19.8%** |
| 4 SICU 外科 | 3,408 | 14.9% |

（方案原文 n 为 1766 / 2530 / 4286 / 3406，称另有 12 例缺 `ICUType`。本评审按每份记录头部描述符抽取，四类均有值、合计 12,000。死亡率比例一致；缺 12 例以特征表冻结时的抽取规则为准。）

### 2.3 方案是菜单，不是展示稿

v2 已经像一篇小论文提纲。展示日时长 9/21 才问得清，塞不下 T1+T2+T3 + 四套差异化 + 三条 limitation + 校准 + 阈值 + 可解释性。

主线建议就这几页，其余进附录或 Q&A：

1. 第 48 小时这个问题是什么、谁用、改什么行动
2. 数据能撑什么、撑不住什么（泄漏、MNAR、48h 窗口）
3. 预处理为什么这么做（`−1`、血压 0、聚合、缺失指示列）
4. 必须打败的基线
5. 模型对比（含「复杂度的理由」和过拟合图）
6. 工作点：警报预算下的 recall，不是默认 0.5
7. 校准：排序给复核；百分比要说给家属才必须校准
8. 局限 + 建议

差异化建议：

| 打法 | 取舍 | 理由 |
|---|---|---|
| **C 换病房测试** | **必做** | 直接回答「未见数据」+ 亚组 + 校准，三者课件都点名 |
| **A 纯缺失模型** 或 **D 假阴性尸检** | 二选一 | A 成本半天、那句话别组没有；D 把 48h 窗口的固有盲区讲成故事 |
| **B 时间价值曲线** | 若做，T3 并进 B | 比单点 24h 消融更值；不要 B 和 T3 各占一页 |
| 30 天死亡标签 | 留在 limitation | 展示「我们知道 `Survival` 能干什么」即可，不要再开一个任务 |

不要做的路，方案里已经写对：LSTM / 正经生存分析 / 自造机械通气标签。维持。

## 三、T1：框架合适，指标口径咨询课前改顺

问题陈述里叠了两件行动：高年资复核，以及提前启动家属沟通。

Topic 05 的分界是：

- **筛查 / 分配资源** → 排序可能就够（AUC-ROC 当主指标说得通）
- **影响个体临床决策、把数字说给家属** → 校准不是可选项

所以主指标可以仍是 AUC-ROC，但 slide 上要写清：**工作点由警报负担决定，临床决策数字看校准曲线。** 若校准差，就明确说「我们只用来排队复核，不把 40% 这种数说给家属」——这比多一个模型更像这门课要的答案。AUC-PR、阈值–sensitivity–每 100 人告警数，按计划都要报。

「宁可 FP 不可 FN」能成立，前提是行动保持廉价（复核）。不要写成触发临终谈话——v2 已经写了，守住。

T1 预答辩三点（凭什么不替代床旁医生、代价不对称是行动的属性、三条 limitation）都该进 Q&A 清单，尤其是自我实现悖论和 confounding by indication（适应证混杂：因病重才上机，上机又被拿来预测死亡）。

## 四、分工与时间线

六环认领比 v1 更贴要求 04。评估位先造尺子、integrator 与红队分开，都对。人数变动降级路径也写了。沿用。

两个执行风险：

**① 位「基本无代码」在互评里不好看。** Peer evaluation 里「有效地履行职责」占 25%，协作两项合计 60%。这个人必须有看得见的交付物：problem statement 一页、红队问题库、deck 骨架、limitation 初稿、9/21 咨询简报。否则期末互评会吃亏，也难当「9/21 主谈」。

**本周节点和 Quiz 1 抢时间。** 方案写「→8/31 认领 + mob session，9/1 骨架」。Quiz & Practical Test 1 是 **2026-09-03，Topics 01–03**。项目占 40%，但三天后那 1 小时考不过，先伤的是 Quiz。Mob session 本周做（90 分钟走通一个病人）值得；features 冻结 9/10 仍然合理；不要为了骨架把 Quiz 1 复习挤掉。

倒排其余节点没问题：9/17 harness 就绪、9/21 咨询、10/4 前模型完成、10/12 代码冻结、按 10/19 准备展示。9/21 带骨架去，不要带「已经做完的项目」——课件原话就是 *Leave with a direction, not a finished project*。当场问清三件事：代码提交截止日期、本组展示批次、每组展示时长。

## 五、小事实：不伤骨架，但别在咨询课上说错

这些不影响策略，数字错了会被追问。

| 方案原文 | 复算 | 怎么处理 |
|---|---|---|
| 87 例 Survival 与 LOS 互相矛盾 | 按常见定义复现不出 87。院内死亡者 `LOS − Survival` 中位数是 1 天，更像计日口径；存活却 `Survival < LOS` 约 3 例，外加 `Survival = −23` 1 例 | limitation 里提数据质量可以，数字重算后再写 |
| T2「猜均值 8.13 vs 猜中位数 7.42」写在幸存者段落 | 这是**全体有效 LOS**（含死亡，n=11,833）的数；幸存者子集（n=10,126）约为 8.00 vs 7.30 | 数字跟分析队列对齐 |
| 2,882 名存活出院者随访期内有死亡日期 | `Survival ≠ −1` 且院内存活 = 2,883，其中含 `Survival = −23` 1 例；排除后 2,882 | 原文按排除无效值算是对的 |
| `ICUType` 缺 12 例；n = 1766 / 2530 / 4286 / 3406 | 头部描述符抽取四类均有值：1769 / 2530 / 4293 / 3408 | 冻结特征表时定抽取规则；死亡率比例可沿用 |

另外两处实施时就会碰到，方案里写得不够硬：

- **特征会很宽。** 每个变量 6 个统计量 + 「是否测过」指示列，轻松 200+ 列。T1 的 LogReg 也需要正则，不要只有 T2 才做 Ridge/LASSO。相关生命体征会瓜分 permutation importance——方案已写「成组解读」，做图时必须守这句，否则 HR / MAP / 有创血压会打成一团。
- **亚组不只 ICU 类型。** Topic 05 点名 age bands、sex，以及「永远不要只报一个总体数字」。打法 C 覆盖了 site / case mix；年龄和性别至少在附录报一组。

## 六、改完之后的策略（一页收口）

- **选题不换**：T1 院内死亡（主打）+ T2 剩余住院日（回归）+ 时间窗消融并进打法 B（若做）或保留单点 T3。
- **T1 框架不换**，slide 上分清「排序给复核」和「数字给家属」。
- **T2 任务不换，故事要改**：全体剩余住院日为主，幸存者分析降为敏感性分析；去掉那条占用公式。
- **v2 分工不换**：① 补齐可见交付物。
- **差异化要砍**：C 必做；A / D / B 最多再挑一个。
- **切分补一层**：train / val / test（或 train 上 CV + 锁死 test）；跨样本变换只在 train 上 fit。
- **最大风险不是策略错，是策略过满。** 评分链条讲透，比多一个消融实验值钱。

Quiz 1 过完，9/10 前真正该冻结的只有三样：`features.csv`、RecordID 切分文件（含 validation）、T1 三个基线 + T2 中位数基线跑通。
