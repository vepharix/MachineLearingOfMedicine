# 小组项目要求汇总

> 官方信息散在四处：OBTL、Course Schedule、Session 1 课件、Session 2 课件（8/26 那节）。这里合并成一份。
> 整理时间 2026-08-26。数据集本身另见 [数据集速览.md](数据集速览.md)。

## 一、占分与构成

**总计 40%，是三块考核里最重的一块**（Quizzes 30% / Practical Test 30% / 本项目 40%）。

| 项 | 占模块 | 评什么 |
|---|---:|---|
| **Project code** | **20%** | 完整、可复现的 pipeline；预处理、模型对比、评估都要有理由 |
| **Presentation + Q&A** | **15%** | 清晰的临床故事；主张旁边要有证据；**每个成员都要能为整个项目辩护** |
| **Peer evaluation** | **5%** | 贡献度、准备程度、团队协作 |

课件原话：**"The project is 40% – marks reward the reasoning chain. A higher model score is not enough without a defensible clinical and analytical story."**

评分看的链条是：**clinical question → data → preprocessing → model comparison → metric → recommendation**。分数不是给模型跑得高的，是给这条链条完整且站得住的。

## 二、四条硬性要求

课件写明是 **minimum requirements**，数据支持的话鼓励超出。

| | 要求 | 细则 |
|---|---|---|
| **01 ASK** | **至少 2 个预测任务** | 从 ICU 记录里选至少两个结局/预测目标。**可以超出 outcomes.csv 提供的那几个**，也可以加别的分析 |
| **02 BUILD** | **模型必须自己训** | ⚠️ **不许用外部预测 API**。欢迎更复杂的模型，但复杂度要有理由 |
| **03 EVALUATE + EXPLAIN** | 指标要选得对并说明理由 | 报告**各个数据划分上**的表现，**包括未见数据**；**每个预测模型都要提供可解释性** |
| **04 INTERPRET + DEFEND** | 临床意义要清楚 | 结论要有分析证据支撑。**讲师和 TA 会提问，每个组员都要懂整个项目** |

## 四、咨询课要带走的三样东西

Session 2 课件把咨询定位成「**Leave with a direction – not a finished project**」，要求当场定下三件事：

| | 问什么 | 带走什么 |
|---|---|---|
| **1 USER + DECISION** | 谁会用这个预测？什么行动会因此改变？ | **一句话的 problem statement** |
| **2 DATA + BASELINE** | 数据能支撑什么？**必须打败的简单参照是什么？** | **主指标**，且与临床代价挂钩 |
| **3 METRIC + BLOCKER** | 哪种错误更要命？下一个要解决的是什么？ | **下一个 blocker** |

这三问和 Topic 05 讲解里「把含糊需求变成规格的四问」是同一套东西，可以直接套。

## 五、Peer evaluation 怎么打分（OBTL 附录）

1–9 分，四个维度加权：

| 维度 | 权重 | 看什么 |
|---|---:|---|
| 尽责地履行职责 | 15% | 准时参会、参与讨论、按时完成分工 |
| 有效地履行职责 | 25% | 产出质量、想法创造性、研究与思考的深度 |
| 处理人际关系 | 30% | 倾听、化解冲突、促进共识、尊重差异 |
| 支持他人达成目标 | 30% | 分担责任、给予署名、帮助他人学习、必要时为他人发声 |

⚠️ 注意后两项合计 **60%** —— 这份评分表里，**协作占的分比产出还多**。

## 六、给我们这组的具体建议

数据集的完整体检见 [数据集速览.md](数据集速览.md)，与作业要求直接相关的几条：

- **「至少 2 个预测任务」的自然选法**：① `In-hospital_death`（二分类，14.2% 阳性）② `Length_of_stay`（回归）。两个任务正好各用一次 Topic 03 和 Topic 04 的东西。第三个可以自己造，比如「48 小时内是否需要机械通气」。
- **⚠️ 建模前必须先丢 `Survival`** —— 它是完美泄漏源，1707 例死亡全部有值。
- **基线要打三个**：全猜存活（85.8%）、只用 SAPS-I、只用 SOFA。课件明确要求 "What simple reference must you beat?"
- **可解释性是硬要求**（要求 03），不是加分项。每个模型都得配 —— 逻辑回归给 odds ratio，树模型给 feature importance + SHAP/PDP。
- **每个人都要能讲全项目**（要求 04），所以别按「你做预处理我做建模」切分到底，最后要留时间互相过一遍。
